# PX4 SITL rig (`sitl/`)

Tests our code on the drone's real software path before a physical test. The rig runs PX4 **v1.16.2**, the drone's
firmware, from the `sitl/PX4-Autopilot` submodule. It uses ROS 2 **Humble** and skybeta's own `flight_interface` and
`px4_odom_bridge`, built from the read-only skybeta checkout, plus our `skybeta.launch.py`. It is for evaluation only,
never a training target. The rig is untested so far: nothing below has run yet (see "Status").

## What runs
Everything runs in one container (`sitl/run_rig.sh`, `sitl/rig_entry.sh`). It is the same on the Jetson (arm64) and on
an x86 lab PC.

| piece | stands in for | notes |
|---|---|---|
| Gazebo Harmonic, headless, our course (`sitl/world/`) | the room | world exported from dronehacks-sim by `export_world.py` |
| `x500_skybeta` (`sitl/models/`) | the airframe | x500 dynamics. Forward depth camera on the OAK mount (`CAMERA_*`), 640x400 at 74.7 x 51 deg. Down rangefinder with 4 m range, like the VL53L1X; PX4's `gz_bridge` turns it into `distance_sensor` |
| PX4 SITL v1.16.2, airframe `4090_gz_x500_skybeta` | the Pixhawk 6C | generated by `sitl/params.py` (see Parameters) |
| `MicroXRCEAgent udp4 -r agent_refs_local.xml` (v2.4.3) | skybeta's `run_agent.sh` | `UXRCE_DDS_PTCFG=2`, as on every FC |
| `sitl/gz_vio.py` -> `/visual_slam/tracking/odometry` | cuVSLAM | odom frame is the startup pose (arbitrary heading), body-frame twist, about 65 ms latency, noise and drift, optional outage |
| `px4_odom_bridge` (skybeta's, via its `px4_bridge.launch.py`) | skybeta's `run_bridge.sh` | ENU->NED, `POSE_FRAME_FRD`, to `/fmu/in/vehicle_visual_odometry` |
| `sitl/gz_depth.py` -> `/policynav/depth/image` + camera_info + TF | our stereo (`vpi_stereo`) | 32FC1 m, NaN invalid, readings under 0.33 m -> NaN, optional noise and dropout |
| `run_rig.sh team` = `skybeta.launch.py stereo_backend:=none` | the stack's competitor window | `flight_interface` + `skybeta_policy`, exactly as on the drone |
| `sitl/pilot.py` | the safety pilot and the RC transmitter | MAVLink `MANUAL_CONTROL` (`COM_RC_IN_MODE=1`): arms in Altitude, switches to Position, waits for Offboard, takes over with the throttle, lands |

**DDS:** every process uses skybeta's `host/dds/fastdds_localhost.xml` (mounted read-only) and domain **150**.

**Isolation:** the rig runs in its own network and IPC namespace, DDS stays on the container's loopback, and domain
150 is outside the fleet's 1..99. So it is safe to run on a drone whose real stack is up.

## Commands
```bash
git submodule update --init --recursive        # sitl/PX4-Autopilot at v1.16.2 (~3 GB with submodules)
sitl/run_rig.sh build                          # image (once), PX4 SITL, the ROS workspace; JOBS=n caps parallelism
sitl/run_rig.sh build ws                       # after changing policynav or pulling skybeta (fast)
sitl/run_rig.sh up                             # waits for READY; logs in the container under /tmp/rig/*.log
sitl/run_rig.sh team                           # our launch (another terminal); extra args pass through, e.g. policy:=...
sitl/run_rig.sh pilot fly                      # DRY RUN: checks PX4, prints the plan, arms nothing
sitl/run_rig.sh pilot fly --arm                # the competition flow; needs the team's OK for this run (AGENTS.md)
TEAM_LAUNCH=skybeta_climb_forward.launch.py sitl/run_rig.sh team fly:=true   # the scripted test flight instead
sitl/run_rig.sh pilot status | sh | logs | down
```

`pilot fly --arm` prints a JSON summary when it finishes, with these fields:
- time to arm
- Offboard latency after the switch to Position
- autonomy time
- whether Offboard ended by itself
- the takeover and disarm times

The exit code is 0 only if every step happened.

**Options for `up`** (all optional):

| variable | what it does |
|---|---|
| `SPAWN_POSE=x,y,z,roll,pitch,yaw_enu` | start pose; default is the launch mark in `world/spawn.txt` |
| `BATTERY_SOC=0..1` | 4S sag model; scales the motor constants |
| `CAMERA_X/Y/Z/ROLL/PITCH/YAW` | the drone.env keys; default is forward, 0.12 m ahead |
| `PX4_PARAMS_DUMP=sitl/params/<file>` | layer a real FC dump over the fleet files |
| `VIO_LATENCY_MS` (65), `VIO_SIGMA_P`, `VIO_DRIFT_P`, `VIO_DRIFT_YAW` | fake-VIO latency, noise and drift |
| `VIO_OUTAGE_AT_S`, `VIO_OUTAGE_S` | simulated tracking loss |
| `DEPTH_NOISE_K`, `DEPTH_DROPOUT` | depth noise and dropout |
| `SITL_DOMAIN_ID` | DDS domain; default 150 |
| `SKYBETA_DIR` | the skybeta checkout; default `../skybeta`, then `~/skybeta` |

## Parameters
`sitl/params.py` writes the airframe on every start, in three layers (later wins). PX4 starts with fresh parameters
each time.
1. **skybeta's fleet files**, from `skybeta/px4/params/`:
   - `02`: only `UXRCE_DDS_PTCFG=2` and the key; not the serial-port settings
   - `03a`: range height reference with baro on
   - `03b`: EV fusion, `EV_DELAY` 70
   - `04`: `FD_FAIL_R`
   - `08`: no optical flow
   - `09`: `COM_RC_OVERRIDE=3`
2. **A drone dump**, if `PX4_PARAMS_DUMP` is set. Only the estimator, failsafe, navigation and envelope families are
   taken (`DUMP_ALLOW` / `DUMP_DENY` in `params.py`). Never rate gains, rotor geometry, hover thrust, calibration, RC
   or serial settings: the SITL vehicle is an x500.
3. **`sitl/px4_params.txt`**: what SITL must differ in:
   - `COM_RC_IN_MODE=1`: `pilot.py` instead of a transmitter
   - `NAV_DLL_ACT=0`
   - the 4S battery

## Limits
The rig stands in for the drone; it is not the drone:
- **x500 dynamics**, not our airframe: mass, motors and rate gains differ. Replace them once the motor/prop data and
  the FC dump are in.
- **No cuVSLAM and no stereo:** VIO is truth plus a noise model, and depth is a perfect depth camera (optionally
  noised). It tests our logic and the PX4/skybeta interfaces, not vision robustness. There is no
  `/visual_slam/status` (the Isaac message type is not in the rig), so the bridge's `reset_counter` stays 0.
- **The sim must hold about 1x real time.** skybeta's nodes stamp with the wall clock (as on the drone), so a slow
  Gazebo shows up as EV latency. Check `gz.log` and the `Hz` lines in `vio.log` / `depth.log`.
- **The net is an invisible collision shell.**
- The battery model is static per flight; SITL's own reported voltage does not follow it.

## Gotchas
- gz-physics segfaults on OBJ meshes without normals. `add_normals.py` adds them.
- With snap Docker, use `--runtime nvidia`, not `--gpus all`. ogre2 needs the glvnd EGL vendor file, which the image
  carries.
- `px4-rc.gzsim` (v1.16.2) applies only x y z of `PX4_GZ_MODEL_POSE`, so `rig_entry.sh` spawns the model itself and
  PX4 attaches to it (`PX4_GZ_MODEL_NAME`).
- `ros_gz` for Humble + Harmonic is not packaged for arm64, so the gz->ROS bridges use Gazebo's Python bindings
  (`python3-gz-transport13`).
- rcS copies `ROS_DOMAIN_ID` into `UXRCE_DDS_DOM_ID`. That is how PX4 joins the rig's domain.
